# 商品价格与库存监控 PRD

## 1. 项目概述

本项目用于监控商品的价格和库存信息。用户通过 Excel 导入需要监控的 URL 列表；每个 URL 可能关联多个商品，系统需要从 URL 对应页面中提取商品名称、价格和库存，并将结果保存到本地数据库中，供用户查询。

项目主要包含两个部分：

- Pages：提供用户操作页面，用于导入 Excel、维护监控 URL 列表、展示监控报警，并按商品名称模糊查询商品信息。
- Workflows：提供后台工作流，读取监控参数后遍历所有需要监控的 URL，调用商品提取接口，更新商品价格和库存数据，并记录商品缺失、价格上涨和低库存等命中情况。

## 2. 功能范围

### 2.1 Pages 页面能力

页面位于 `src/pages` 目录，负责面向用户的导入和查询能力。

页面需要支持以下功能：

- 监控报警：
  - 页面默认展示 `监控报警` 列表，并在 tab 中显示当前报警总数。
  - 监控报警列表读取 `ProductAlert` 表中的数据。
  - 监控报警列表按 `checkedAt` 时间倒序展示；时间相同时按记录 `id` 倒序展示。
  - 监控报警列表支持分页展示，每页固定 20 条，并提供上一页和下一页切换。
  - 每条报警需要展示 `No.` 序号、商品名称、规格、命中类型、来源 URL 和检查时间。
  - 命中类型需要转换为中文展示：`missing` 显示为 `商品缺失`，`price_increase` 显示为 `价格上涨`，`low_stock` 显示为 `低库存`。
  - 同一条报警命中多个类型时，需要在同一个命中类型单元格中按每种类型一行展示。
  - `price_increase` 类型行需要展示带人民币标识 `¥` 的价格变化，`low_stock` 类型行需要展示不带币种的库存变化。
  - 来源 URL 需要可点击打开原始页面。
  - 页面在 `导入URL` 按钮旁提供 `生成测试报警` 按钮，用于基于 `Product` 表生成报警测试数据。
  - 点击 `生成测试报警` 时，如果 `Product` 表为空，需要提示 `暂无商品数据，无法生成测试报警。`，且不修改 `ProductAlert` 表。
  - 点击 `生成测试报警` 时，如果 `Product` 表存在数据，需要先清空 `ProductAlert` 表，再生成 20 条测试报警。
  - 测试报警需要覆盖单命中类型 `missing`、`price_increase`、`low_stock`，以及多命中类型 `price_increase + low_stock`。
  - 商品数量不足 20 条时，测试报警按已有商品循环复用商品名称、规格和 URL，不修改 `Product` 表。
- Excel 导入：
  - 用户上传 Excel 文件。
  - Excel 文件必须包含固定表头 `上游1`。
  - 系统读取 `上游1` 列中的所有非空 URL。
  - URL 导入采用合并去重模式：已有 URL 保留，新 URL 写入监控列表，重复 URL 不重复插入。
- 参数设置：
  - 页面在 `导入URL` 按钮右侧提供 `设置` 按钮。
  - 设置弹窗包含 `每小时监控速率` 和 `库存预警值` 参数。
  - 设置参数保存到数据库中的全局设置记录。
  - `每小时监控速率` 默认值为 `180`（每分钟 3 个），允许范围为 `1-360`，用于控制工作流每小时最多请求多少个有效 URL。
  - `库存预警值` 默认值为 `100`，必须为大于等于 `1` 的整数。
  - 页面生成测试报警和工作流低库存判断都必须读取数据库中的库存预警值。
- URL 监控列表：
  - 保存用户导入的待监控 URL。
  - 页面可展示当前已导入 URL 数量。
  - URL 监控列表支持分页展示，每页固定 20 条，并提供上一页和下一页切换。
  - 列表中每条 URL 需要展示 `No.` 序号和该 URL 当前已提取到的商品数。
  - 用户可以将某条 URL 手动标记为失效；失效 URL 继续展示在列表中，状态列显示 `失效`。
  - 用户可以将失效 URL 恢复为有效。
  - 用户点击某条 URL 后，直接打开一个新的页面展示该 URL 的原始页面内容。
  - 用户点击某条 URL 对应的商品数后，跳转或切换到商品查询区域，并展示该 URL 对应的商品信息。
- 商品查询：
  - 用户可以通过商品名称进行模糊匹配查询。
  - 用户可以基于 URL 查询商品信息。
  - 商品名称查询和 URL 查询可以组合使用；同时输入时，结果需同时满足商品名称和 URL 条件。
  - 商品查询搜索栏左侧展示当前查询结果数量，文案为 `已查询到xxx件商品。`。
  - 商品查询结果支持分页展示，每页固定 20 条，并提供上一页和下一页切换。
  - 查询结果展示 `No.` 序号、商品名称、价格、库存、来源 URL、更新时间等信息。
- 结果反馈：
  - Excel 缺少 `上游1` 表头时，需要给出明确错误提示。
  - 导入完成后，需要反馈新增 URL 数、重复 URL 数、无效或空 URL 数。

### 2.2 Workflow 工作流能力

工作流位于 `src/workflows` 目录，负责批量更新商品数据。

工作流需要支持以下功能：

- 读取数据库中所有待监控 URL。
- 跳过已手动标记为失效的 URL；失效 URL 不调用商品提取 API，也不更新该 URL 下的商品数据。
- 对有效 URL 逐个调用现有商品提取 API。
- 从 API 返回结果中解析商品数组。
- 将每个商品的名称、规格、价格、库存和来源 URL 写入商品表。
- 同一个 URL 下同名同规格商品再次出现时，更新价格、库存和更新时间。
- 每个 URL 获取到新商品数据后，需要先读取数据库中该 URL 关联的所有历史商品，并与本次结果按 `[name + spec + url]` 对比。
- 命中以下任一情况时，需要向商品命中记录表追加一条记录：
  - 商品在数据库中存在，但本次获取结果中不存在，且历史库存不为 `0`，视为商品已无库存。
  - 数据库中的商品价格低于本次获取到的商品价格。
  - 本次获取到的商品库存数低于数据库中的 `库存预警值`。
- 同一商品在同一轮检查中命中多种情况时，只写入一条命中记录，并在记录中保存全部命中类型。
- 单个 URL 处理失败时，不阻断其他 URL 的处理。
- 工作流执行结果需要返回处理摘要，包括成功 URL 数、失败 URL 数、更新商品数、命中记录数和错误摘要。

## 3. 已确认业务规则

- Excel 导入文件必须包含固定表头 `上游1`。
- URL 导入采用合并去重模式，不清空已有监控 URL。
- 重新导入已存在 URL 不改变其失效状态；失效 URL 必须通过列表操作恢复为有效。
- 一个 URL 可以包含多个商品信息。
- 商品唯一性按 `[name + spec + url]` 判断，即同一个 URL 下商品名称和规格都相同才视为同一商品。
- 同一 URL 重新抓取后，如果某个历史商品本次未被提取出来，说明该商品已经没有库存，需要将该商品库存标记为 `0`。
- 同一 URL 重新抓取后，如果某个历史商品本次未被提取出来，且历史库存已经是 `0`，不再重复追加商品缺失命中记录。
- 商品低库存阈值从全局设置中的 `库存预警值` 读取，默认值为 `100`；库存小于该阈值时命中低库存，库存等于该阈值不命中。
- 低库存命中适用于本次 API 返回的所有商品，包括数据库中原本不存在的新商品。
- 如果本次库存和数据库中的历史库存都小于当前低库存阈值，说明该商品此前已经处于低库存状态，不再重复追加 `low_stock` 命中记录。
- 商品命中记录采用追加模式；同一商品在不同工作流轮次中重复命中时，会生成新的命中记录，不覆盖历史记录，但持续低库存状态不会重复追加 `low_stock` 记录。
- 商品命中记录只保留 `checkedAt` 一个时间字段，用于表示该命中是在本次 URL 检查时发现的。
- 页面 tab 顺序固定为：`监控报警`、`URL监控`、`商品查询`。
- `监控报警` 是页面默认首屏；商品查询搜索栏只在 `商品查询` tab 下展示。
- 三个页面列表均展示 `No.` 列；序号按当前列表排序和分页后的全局位置计算，第 2 页第一条显示为 `21`。
- `生成测试报警` 是页面测试辅助能力；生成前允许清空已有 `ProductAlert` 记录，但不新增测试标记字段，不修改 `Product` 表。
- 页面中所有价格展示都需要带人民币标识 `¥`；库存等非价格数字不带币种。
- 商品查询支持按商品名称模糊匹配，也支持按 URL 查询；从 URL 监控列表点击商品数时，应复用 URL 查询能力展示对应商品。
- URL 监控列表中的 URL 和商品数是两个不同的可点击目标：点击 URL 打开原始页面，点击商品数筛选商品查询结果。
- URL 监控列表和商品查询列表每页展示 20 条记录；分页只影响页面展示，不影响监控 URL 总数、商品数统计或工作流处理。
- API 单个 URL 调用失败时，需要记录失败信息并继续处理后续 URL。
- 工作流按有效 URL 串行执行，并根据全局设置中的 `每小时监控速率` 控制相邻请求开始时间的最小间隔；请求运行耗时计入该间隔。首轮全部完成后，对本轮失败的 URL 再串行重试一次。
- 如果 API 提取结果返回 `["captcha-required"]`，工作流需要写入当前 URL 的错误信息并立即停止，不继续处理后续 URL，也不执行失败 URL 重试。
- 全局设置只保留一条 `id = global` 的记录；首次缺失时使用默认值初始化。

## 4. 数据模型

### 4.1 Source

`Source` 表用于保存待监控 URL。

字段定义：

- `id`：数据库自增主键。
- `url`：商品所在 URL，唯一。
- `createdAt`：首次导入时间。
- `updatedAt`：最近更新 URL 记录的时间。
- `lastCheckedAt`：最近一次工作流检查该 URL 的时间。
- `lastError`：最近一次处理该 URL 的错误信息；处理成功时清空。
- `isInvalid`：是否已被用户手动标记为失效 URL。
- `invalidAt`：最近一次手动标记失效的时间。

### 4.2 Product

`Product` 表用于保存商品信息。

字段定义：

- `id`：数据库自增主键。
- `name`：商品名称。
- `spec`：商品规格。
- `url`：商品来源 URL。
- `stock`：商品库存。
- `price`：商品价格。
- `updatedAt`：最近一次更新商品信息的时间。

唯一约束：

- `[name + spec + url]` 唯一。

### 4.3 ProductAlert

`ProductAlert` 表用于保存工作流检查过程中发现的商品命中记录。

字段定义：

- `id`：数据库自增主键。
- `url`：商品来源 URL。
- `name`：商品名称。
- `spec`：商品规格。
- `hitTypes`：本次命中的类型数组，可包含 `missing`、`price_increase`、`low_stock`。
- `previousPrice`：数据库中原价格；无历史商品时为空。
- `currentPrice`：本次获取到的新价格；商品缺失时为空。
- `previousStock`：数据库中原库存；无历史商品时为空。
- `currentStock`：本次获取到的新库存；商品缺失时为空。
- `stockThreshold`：本次命中使用的低库存阈值。
- `checkedAt`：本次工作流检查时间。

索引：

- `url`、`name`、`spec`、`checkedAt`。
- `[name + spec + url]` 用于按商品唯一键查询命中记录。

### 4.4 AppSettings

`AppSettings` 表用于保存页面和工作流共享的全局参数设置。

字段定义：

- `id`：固定为 `global`。
- `monitorHourlyRate`：每小时监控请求数，默认 `180`（每分钟 3 个），范围 `1-360`。
- `stockAlertThreshold`：库存预警值，默认 `100`，最小值 `1`。
- `updatedAt`：最近一次设置更新时间。

索引：

- `id` 唯一。
- `updatedAt`。

## 5. 外部接口

复用现有 `get_sku_list_from_url(product_url)` API。

接口用途：

- 输入：单个商品页或商品列表页 URL。
- 输出：商品数组，每个商品至少包含商品名称、规格、价格和库存。

工作流需要对接口返回值做必要解析和容错：

- 优先从 `task.extract_data` 中读取提取结果。
- 当 `task.extract_data` 可解析为数组且第一个元素为 `captcha-required` 时，视为验证码拦截并停止当前工作流。
- 结果应解析为商品数组。
- 商品名称为空的记录应跳过。
- 商品规格为空的记录应跳过。
- 价格和库存需要转换为数字；无法转换的记录应跳过或按实现中的错误策略处理。

## 6. 验收标准

### 6.1 Excel 导入

- 用户可以上传包含 `上游1` 表头的 Excel 文件。
- 系统能读取 `上游1` 列并保存待监控 URL。
- 重复 URL 不会重复插入。
- 缺少 `上游1` 表头时，页面显示明确错误信息。

### 6.2 监控报警

- 打开页面时默认展示 `监控报警` tab。
- `监控报警` tab 数字显示当前数据库中的报警总数。
- 监控报警列表能展示 `No.` 序号、商品名称、规格、命中类型、来源 URL 和检查时间。
- 监控报警列表按 `checkedAt` 时间倒序展示；时间相同时按记录 `id` 倒序展示。
- 监控报警列表每页展示 20 条记录，支持上一页和下一页。
- 同一报警有多个命中类型时，命中类型在同一个单元格内按每种类型一行展示。
- `price_increase` 类型行显示带 `¥` 的价格变化，`low_stock` 类型行显示不带币种的库存变化。
- 价格或库存的新旧值为空时，页面显示 `-`，不显示 `undefined`。
- 点击报警来源 URL 后，页面会打开一个新的页面展示该 URL 的原始页面内容。
- 没有报警记录时，页面显示空状态。
- `Product` 表为空时，点击 `生成测试报警` 显示错误提示，并且不修改报警记录。
- `Product` 表存在数据时，点击 `生成测试报警` 会清空旧报警并生成 20 条新报警。
- 生成的测试报警包含单命中记录和多命中记录，至少覆盖 `missing`、`price_increase`、`low_stock`、`price_increase + low_stock`。
- 商品数量少于 20 条时，测试报警仍生成 20 条，并循环复用已有商品信息。

### 6.3 商品查询

- 用户可以输入商品名称关键字进行模糊查询。
- 用户可以输入或选择 URL 查询该 URL 下的商品信息。
- 用户从 URL 监控列表点击某条 URL 的商品数后，商品查询区域展示该 URL 对应的商品信息。
- 商品查询 tab 数字显示当前数据库中的商品总数。
- 商品查询搜索栏左侧显示 `已查询到xxx件商品。`，数量与当前查询结果总数一致。
- 商品查询结果每页展示 20 条记录，支持上一页和下一页。
- 查询结果能展示 `No.` 序号、匹配商品的名称、规格、带 `¥` 的价格、库存、来源 URL 和更新时间。
- 当没有匹配商品时，页面显示空状态。

### 6.4 URL 监控列表

- URL 监控列表能展示每条 URL。
- URL 监控列表每页展示 20 条记录，支持上一页和下一页。
- 每条 URL 能展示 `No.` 序号和当前从该 URL 提取到的商品数。
- URL 被标记为失效后，状态列显示 `失效`，并可恢复为有效。
- 点击某条 URL 后，页面会打开一个新的页面展示该 URL 的原始页面内容。
- 点击某条 URL 对应的商品数后，页面能跳转或切换到商品查询展示，并筛选出该 URL 下的商品。

### 6.5 工作流更新

- 工作流能读取所有待监控 URL，并跳过已标记失效的 URL。
- 工作流能逐个调用 `get_sku_list_from_url(product_url)` 处理所有有效 URL，并按 `每小时监控速率` 控制相邻请求开始时间的最小间隔。
- API 返回多个商品时，系统能分别写入或更新商品表。
- 某个 URL 调用失败时，其他 URL 仍继续处理。
- API 返回 `["captcha-required"]` 时，当前 URL 写入中文 `lastError`，工作流立即停止且不触发重试。
- 同一 URL 下历史商品本次未出现在 API 结果中时，该商品库存更新为 `0`。
- 同一 URL 下历史商品本次未出现在 API 结果中，且历史库存不为 `0` 时，追加一条 `missing` 命中记录。
- 数据库中历史商品价格低于本次获取价格时，追加一条 `price_increase` 命中记录。
- 本次获取商品库存小于数据库中的 `库存预警值`，且数据库中无该商品历史记录或历史库存不小于该阈值时，追加一条 `low_stock` 命中记录；库存等于该阈值不命中。
- 同一商品同一轮命中多种情况时，命中类型保存在同一条记录中，不拆成多条记录。
- 工作流执行完成后返回处理摘要。
- 工作流摘要包含跳过的失效 URL 数和本次新增的商品命中记录数。

## 7. 非目标

当前版本不包含以下能力：

- 用户账号体系和权限管理。
- 多租户隔离。
- 价格或库存变化通知。
- 历史价格曲线。
- 自动定时调度配置页面。
- URL 删除、商品删除等管理操作。
