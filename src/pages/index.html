系统用途

本系统用于监控受支持商品 URL 的价格、库存和异常情况。用户导入需要监控的 URL 后，后台工作流会提取商品名称、规格、价格和库存，并将结果保存到本地数据库，供报警查看、URL 管理和商品查询使用。

导入 URL

  • 点击「导入URL」，上传 Excel、XLS 或 CSV 文件；系统读取第一个工作表。
  • 系统扫描第一个工作表的全部单元格，并提取单元格内容为完整 URL 的记录。
  • 仅支持 http 或 https 的 1688.com、jinritemai.com 及其子域名 URL；其他域名会计入「非支持域名 URL」。
  • 导入采用完整清单同步模式：本次 Excel 中不存在的已导入 URL 会被删除，并同步删除该 URL 关联的商品。
  • 如果导入会删除 URL，系统会先弹窗展示将删除的 URL 数和商品数，确认后才会写入数据库。
  • 重新导入已存在 URL 不会改变其历史状态；如需移除某个 URL，可在「URL监控」中删除。
  • 普通文本、空白值和不完整 URL 会被忽略，不计入「无效或空值」；导入完成后会显示新增 URL、重复 URL、无效或空值、非支持域名 URL、删除 URL 和删除商品的数量。

监控报警

  • 页面顶部 tab 顺序为「URL监控」「商品查询」「监控报警」；首次访问默认展示「URL监控」，刷新后会恢复上次打开的 tab。
  • 「监控报警」顶部数字表示当前报警总数。
  • 报警列表按检查时间倒序排列，时间相同时按记录序号倒序排列。
  • 表头「命中类型」可筛选全部报警、商品下架、价格上涨或低库存。
  • 命中类型包括「商品下架」「价格上涨」「低库存」。同一商品命中多个类型时会在同一单元格内分行展示。
  • 导出时变化信息合并在命中类型列中；价格变化带「¥」标识，库存变化不带币种，缺失值显示为「-」。
  • 点击顶部「导出」并选择「导出监控报警」可导出全部报警；导出后可确认清空本次已导出的报警数据。
  • 点击来源 URL 可在新页面打开原始商品页面；没有报警或筛选后无结果时会显示空状态。

URL 监控

  • 「URL监控」展示已导入 URL、已提取商品数、最近检查时间、状态和操作；顶部数字表示 URL 总数。
  • 点击 URL 打开原始页面；点击商品数会切换到「商品查询」并按该 URL 筛选商品。
  • 表头「状态」可筛选「全部」「正常」「异常」；历史失效 URL 会在「全部」中显示为「失效」。
  • 处理失败的 URL 会在状态列显示错误信息；后续成功处理后错误状态会被清除。
  • 点击顶部「导出」并选择「导出异常URL」可导出全部异常 URL，Excel 包含 URL 和 ID 两列。
  • 点击「删除」前系统会二次确认；确认后该 URL 会从列表移除，并同步删除该 URL 关联商品，历史报警保留。

商品查询

  • 「商品查询」支持按商品名称模糊搜索，也支持按 URL 搜索；顶部数字表示商品总数。
  • 商品名称和 URL 同时填写时，结果需要同时满足两个条件。
  • 搜索栏左侧会显示当前查询到的商品数量；商品按更新时间倒序展示，时间相同时按商品名称排序。
  • 商品价格统一带「¥」标识，库存等非价格数字不带币种；库存为 0 时显示「库存不足」。
  • 点击顶部「导出」并选择「导出商品」可导出全部商品，不受当前搜索条件或分页影响。
  • 三个导出的 ID 均从来源 URL 提取：jinritemai URL 使用 query string 中第一个小写 id 参数值，其他 URL 使用 .html 前路径段的纯数字 ID。
  • 点击商品来源 URL 可在新页面打开原始页面；没有商品或筛选后无结果时会显示空状态。

分页和页面状态

  • 监控报警、URL 监控和商品查询列表每页展示 20 条记录。
  • 可使用「上一页」「下一页」翻页，也可在「跳至」输入页码后点击「跳转」或按 Enter。
  • No. 序号按当前筛选结果和分页位置计算，第 2 页第一条显示为 21。
  • 系统会在本机浏览器中记住当前 tab、筛选条件、搜索关键词和页码，刷新页面后自动恢复。

设置

  • 点击「设置」可配置监控参数。
  • 「每小时监控速率」控制每组每小时最多发起多少次商品提取接口调用，允许范围为 1-360，默认值为 180（每分钟 3 次）。jinritemai 与其他来源独立限速，每个最多包含 90 个 URL 的 jinritemai 批次计为一次调用。
  • 「库存预警值」用于判断低库存，必须大于等于 1，默认值为 100。库存小于该值时会生成低库存报警，等于该值不会报警。
  • 「报警类型」用于激活商品下架、价格上涨和低库存报警，默认全部激活，保存时至少需要激活一种。
  • 关闭报警类型只会停止新增对应报警，不影响商品和库存更新，也不会删除或隐藏历史报警。
  • 设置保存到全局配置中，页面和后台工作流会读取同一份配置。

后台工作流

  • 工作流会跳过已标记失效的 URL；jinritemai URL 每批最多 90 个串行处理，其他 URL 逐个处理，两组分别按设置的每小时监控速率控制请求间隔。
  • 单个 URL 失败不会阻断其他 URL；首轮结束后，本轮失败的 URL 会再串行重试一次。
  • 处理成功时会更新商品价格、库存和 URL 最近检查时间；处理失败时会记录错误并在 URL 状态中显示异常。
  • 同一 URL 下同名同规格商品会被更新；本次没有提取到的历史商品会被标记为库存 0。
  • 商品下架、价格上涨、低库存会生成报警；同一商品同一轮命中多个类型时只生成一条报警记录。
  • 如果接口返回验证码拦截，工作流会为当前 URL 写入错误信息并立即停止，本轮不再处理后续 URL 或执行重试。
